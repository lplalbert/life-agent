# Android 研究平台：模拟器优先

依据用户最新要求：论文研究优先，实用性后置。本文是开发设计，尚未实现测试应用或安装模拟器。

## 目标和实验边界

在原生 Android 环境验证“上下文压缩与故障恢复”的关系。保留真实渲染、无障碍树、系统手势和 Agent 循环，采用虚拟设备消除手机型号、USB、用户账号、真实交易等非必要变量。
机制实验在可控测试应用完成，泛化结论在独立 AndroidWorld 任务验证。模拟器运行仍是在线环境交互，与离线截图选择测试分开报告。

## 三个独立组件

1. Android Agent：复用当前 :app 的 AccessibilityService 与决策循环；新增研究运行模式，固定经验、记录事件、切换上下文策略。
2. 原生 Android 测试应用：计划新增 :research-env 模块，独立 applicationId，不含模型凭证、不联网、不处理真实交易。用原生 View 构造跨页面流程，减少新增依赖。
3. 主机实验控制器：ADB 复位、配置随机种子/故障、读取独立 ground truth、收集 Agent usage；不把隐藏状态或故障标签返回给模型。

Agent 只能通过截图/控件树观察、系统手势操作。控制器和评估器可读隐藏状态；二者的权限与数据通路需与 Agent 逻辑分离。research-env 的控制接口不作为 Agent 工具暴露。
应用控件文字不能包含 fault_id、expected_answer、正确路径提示。测试集中的成功条件不能由 Agent 自报替代。

## 最小场景与防止过拟合

先构造四种开发机制：延迟完成、动作无效果、意外弹窗、相似画面但不同内部状态。
应用层“动作无效果”模拟业务处理失败，不能叫作系统手势投递失败；截图缺失/树过期在观察适配器注入，分别标识。
每类包含正常对照，参数控制布局、文案、目标、干扰项和延迟。相似画面任务要有可取得的区分证据，不能构造信息论上无法完成的任务。
使用真实依赖远期历史的任务，也保留不需要历史的任务；不能只选择有利于证据保留策略的场景。
开发模板和测试模板分离；未见布局、任务组合、故障组合单独报告。多个参数种子不能替代独立任务家族。
自建应用只用于机制因果诊断；不以它代替 AndroidWorld 的独立验证。

## 环境复位和故障协议

每 episode 有唯一 ID、任务/故障种子、环境版本。reset 必须清空业务状态、挂起定时器、故障计数和残留弹窗，并通过独立探针确认。
支持重复同一 seed 得到相同初态；复位失败标记 invalid，不静默重跑并抹去失败。
故障由预定义状态/动作谓词触发；控制器记录 attempted/triggered/recovered。不同策略没有进入触发状态时，不能将其计为恢复成功。
成功检查基于应用内部业务状态及目标参数；模型 finish 文本只作为行为结果记录。
测试应用内完成支付/呼叫外观流程时全部是虚构业务状态，没有外部网络副作用。

## 虚拟设备与性能口径

首先检查本机虚拟化、磁盘和 SDK，之后安装 Android Emulator 和所需 system image；版本、ABI、API、分辨率、密度、locale 与快照必须记录。
研究应用可先使用与项目 compileSdk=34 兼容的 API 34 AVD；AndroidWorld 必须使用其固定版本要求的环境，不能假定两者共用系统镜像。
先单 AVD 串行，确认进程内存和完成耗时再决定并发。所有对照共用规格、冷/热启动政策和渲染设置。
比较完整任务费用与耗时，包含摘要、重新观察、历史取回；图像引用数不是实际 token 或费用。

## 实现顺序与验收

A. 环境：AVD 可启动、ADB 可连接、截图/控件树可读；不需要连接实体手机。
B. 测试应用：四种机制、正常对照、参数化、复位、独立成功检查；先用确定性脚本验证，不消耗模型。
C. Agent：JSONL 事件、冻结经验、full/recent/evidence 策略；不泄漏控制器标签，验证工具请求协议。
D. 端到端 smoke：一个正常和一个受扰任务，检查证据与计费完整性；不以两个案例声称改进。
E. pilot：先固定真实任务 manifest 和预算；执行主规划中的配对实验，再决定扩展。
F. 外部验证：固定 AndroidWorld 版本/任务；实体机和商业 App 兼容可待论文主实验后再做。

当前完成的是设计与离线原型；A–F 均需按实际执行更新台账，不能将本文件当作平台已实现的证明。
