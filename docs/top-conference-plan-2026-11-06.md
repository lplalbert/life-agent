## 1. 论文主线与投稿策略

用户最新定调：研究优先，采用 Android 模拟器与可控 Android 测试应用开展开发和实验；实体机、商业 App 兼容和实用功能后置。实体机连接不再是主实验前置条件。平台设计见 android-research-platform.md。

暂定题目：**Preserving Recovery Evidence under Context Budgets for GUI Agents**。

研究问题：在突发故障和部分可观测条件下，如何在有限上下文中保留恢复任务所需的证据？
核心假设：按“动作效果是否已验证、异常是否已解决”保留证据，能够优于仅按时间保留最近帧。
这是假设，不是已有实验结论；尚未完成最近工作全文对照，不能宣称首创。

第一篇只研究在线工作记忆和恢复，冻结跨任务经验库。不把 ExpeL 式复盘、双通道接入、截图删除或规则提示本身当成新贡献。
第二阶段再研究“经验证的恢复经验”能否跨任务迁移，以及错误经验的撤回；避免第一篇同时改变所有层。

目标以 NeurIPS 2027 方法/评估论文为主；若结果足够早且符合当届征稿范围，再考虑 ICML 2027。
这些是目标会场，不是已确定投稿承诺。ICLR 2027 已于 2026-09-25 AoE 全文截稿，不再作为本轮目标。
截至本次访问，ICML 2027 Dates 页面只列会议日程，未提供可据以排期的论文截止日。NeurIPS 2027 截稿时间未在本轮核实。

## 4. 方法与最小实现边界

在线记录：Observation（各通道时间/状态/引用）、Action（请求与执行结果）、Expectation（可检查的效果）、Verification（pending/failed/verified）。
必须区分“调用成功”“手势被系统接受”“任务相关效果已发生”。未知效果不得自动标 verified。

历史保留策略：最新可用图像 + 未解决检查的证据 + 其余近帧。已验证片段可以压缩成状态变化摘要；丢弃图像仍保留本地原始引用。
证据不足时允许重新观察或检索；这些调用全部计费并计入耗时。不能读取故障注入器标签、未来状态或成功检查器内部数据。
检查器不得事先写入“本步故障”作为输入特征；否则会产生 oracle 泄漏。

首版 research/context_policy.py 只实现因果事件流上的图像引用选择，预算单位为帧数；不是 token 预算器。
它不调用模型，不改 Android 消息，不生成摘要，不证明恢复成功；verification 仍需真实 runtime 产生。
它会报告未被预算容纳的未解决证据，不能以“关键证据”之名无限扩张上下文。

正式集成前还需：
1. 修正/验证 perceive 的成功后重试语义。目前 repeat(3)/repeat(2) 成功后仍继续执行，可能重复采集并扩大时序差。
2. 明确单通道观测时间与降级状态；禁止仅以“以截图为准”统一解决所有过期/缺失情形。
3. 生成运行级 JSONL 事件，输出实际模型/端点版本、调用序号、usage 原始字段、延迟与终态验证结果。
4. 仅在请求构造边界处理历史图像；保持 tool_use/tool_result 配对、thinking 原文和用户文本不变。检查兼容端点协议。
5. 基于实际发送请求验证策略，包括缓存前缀变化。保留原始事件与截图，不覆盖历史证据。

## 5. 实验协议

实验分两层，均以 Android 模拟器运行。机制层使用自建原生 Android 测试应用，控制状态、故障、复位和评估；泛化层使用固定提交/环境的 AndroidWorld。
自建应用不能独自支撑通用 GUI Agent 改进的结论。AndroidWorld 官网记录含 116 个可程序化任务、20 个 App；实际可运行任务及排除理由需列出。生活服务真机矩阵属于可选后续验证，不纳入本轮论文关键路径。

第一轮 pilot：先从已验证可运行的任务中挑选 12 个开发实例，覆盖至少 4 个任务家族。
必须先固定真实任务 ID、参数、初始化/成功/清理器并生成 manifest；目前尚未完成映射，不编造任务 ID。
每实例 5 条件（正常 + 4 故障）× 3 策略（full/recent2/evidence2）× 1 种子 = 180 episode。
先用开发集排查执行协议，再增加 3 种子；验证集和测试集不得用于调参或经验复盘。
最终扩大任务家族、第二模型、未见故障组合，具体样本量由 pilot 方差和最小有意义效应决定。

故障条件：
- 动作丢失：执行边界丢弃预定动作；真实环境效果由独立成功检查确定。
- 延迟观察：固定延迟/旧帧干预；明确这是观测故障，不冒充真实网络延迟。
- 单通道缺失或过期：分别报告截图缺失/树过期，不将不同条件混成一种。
- 意外弹窗/页面中断：可恢复、可复位；不能污染原任务状态初始化。
额外的真实息屏验证单列；ADB 看门狗干预与 Agent 自主恢复分开报告。

配对与数据拆分：
- 配对键为 task_id、参数种子、故障类型/触发条件、重复种子；跨方法使用同一初始快照。
- 不同方法轨迹长度不同时，按预定义动作/状态谓词触发；未触发的 episode 单列，不算“成功恢复”。
- 开发/验证/测试按任务模板或任务家族拆分，不能只换商品或随机参数。
- 在线自学习关闭；经验文件、提示词、工具与模型固定。故障控制器/评估器与 agent 可见事件隔离。
- 随机化执行顺序；记录 API 失败、无法复位、超时、人工介入，不能悄悄剔除失败运行。
- 模型预算、最大步数、观察/恢复机会相同；完整历史作为不受帧预算限制参考另列。

基线：full、recent1/2/4、固定长度摘要、通用关键帧、evidence。摘要和关键帧使用的额外模型调用都计入成本。
公平比较需同时报告帧预算匹配和实际费用匹配，不能仅用相同图片数声称相同 token。
消融：去验证状态、去通道新鲜度、去历史取回、仅重试策略；不要为每个微小实现细节堆砌实验。

主要指标：
- 总体任务成功率；受扰任务成功率，分故障类型报告。
- 故障触发后在限定预算内恢复并完成的比例；注明分母和未触发数。
- 故障检测延迟、重复无效动作、错误宣告成功、人工介入、看门狗恢复。
- 未缓存输入/缓存读/缓存写/输出分别报告，原始 usage 保留；计费口径向实际 provider 核实。
- 每 episode 费用和时延（包含失败运行）；另报告每成功任务的总支出，不只统计成功样本。
- 若声称计算效率，测 CPU 时间、进程族峰值内存，分别列冷/热；未测量则明确未测量。

统计：任务家族/模板为聚类单位，做配对差异与聚类 bootstrap 置信区间；预先固定主比较和主指标。
只有约 4 家族的 pilot 不足以稳定推断泛化；不能把大量参数变体当独立样本夸大显著性。
费用不得从图像字节数或缓存读 token 大小直接推断；减少旧帧可能改变缓存命中。

## 7. 论文结构与需要的图表

Introduction：压缩历史可能移除恢复证据这一矛盾，避免把通用手机助手功能清单当贡献。

Analysis：远期证据依赖、通道冲突、失败案例、成本与缓存影响。
Limitations：模型漂移、故障注入与真实故障差距、用户数据、难复位生活 App。

主图：成功率—实际费用 Pareto 曲线；不同故障/长历史任务的恢复差异；一个真实前后证据链案例。
主表：两模型下正常/受扰成功率、错误终止、费用、时延及样本数；主消融表。
